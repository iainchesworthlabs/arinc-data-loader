**`adl_mock --scenario` makes the mock target misbehave from a file, so that a run with faults can be repeated.** A scenario file is a list of steps, each with a trigger (the nth request, the nth status file, or a time since the operation began) and an action (WAIT, a refusal with 0x1000 or 0x1002, an invalid initialization file, a lost status file, an abort, silence, a corrupted file, a wrong check value option, or a delay), and a seed that fixes every chance, so the same file shows the same faults at the same moments. With `--scenario` the program also writes a `scenario_step` event for each step that fires, and `stopped` lists the steps that never did. A file that cannot be used ends the program with the new exit code 5 and one sentence that names the step. The file is described in [Scenarios for the mock target](docs/user-guide/mock-scenarios.md); the mock target's window does not take one yet.
