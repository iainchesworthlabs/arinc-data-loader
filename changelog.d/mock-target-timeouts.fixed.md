**The mock target now ends an operation whose loader has gone away, and one that the loader aborted with a code of its own.** Before, `adl_mock` and the mock target's window went on writing status files for ever to a loader that had been closed or had stopped answering, and answered nothing after a loader said ABORT with a code that is not one of the three that the standard gives; no later request was served until the program was started again. Now a status file that cannot be delivered (after the two seconds and the retry of the standard, eight seconds in all) ends the operation, with the status 0x1003 (aborted by the target) in `operation_ended`, and an ABORT with another code is answered with 0x1004 and ends it. The page also says what the target does when the acknowledgement of the last block of an initialization file is lost: it sends the block again after two seconds. See [the mock target](docs/mock-target.md).
