**`adl_load --scenario` makes the loader do something wrong on purpose, so that a supplier can see how a target reacts.** A scenario file is a list of steps, each with a moment (the nth request of the target, the nth status file it writes, or a time since the operation began), the datagrams of the loader it applies to, and an action: drop one, send it several times, delay it, hold it back until after the next, change one byte or the check value, make it longer or shorter, replace it with an ERROR, a WAIT or an ABORT, go silent for a while, or abort at that moment. A seed fixes every chance, so the same file gives the same faults at the same moments. With `--scenario` the program also writes a `scenario_step` event for each step that acts, `started` says which file was read, and `finished` lists the steps that never did. A file that cannot be read or is refused ends the program with exit code 5 and one sentence that names the step, before anything is opened. The commands say what the loader did and how the operation ended, and never that a target is right or wrong. `find` and `serve` do not take the option, and a platform that has no scenario libraries refuses it with a sentence. Without it nothing changes. The file is described in [The loader's scenario file](docs/file-reference.md#loader-scenario-file), the options and events in [Command line and exit codes](docs/user-guide/command-line.md#adl_load) and [the command adl_load](docs/load-command.md#--scenario-faults-on-purpose).
