**A scenario for the mock target can now lose, repeat, delay or reorder the datagrams it sends.** Four actions act on single datagrams: `delay` (which now holds back the datagrams a step names, not only the next one), `drop_datagram`, `duplicate_datagram` and `reorder_datagram`. A step can say which datagrams it is for (`on`: the kind, the file, the block) and how many (`count`), and a chance (`per_mille`) is drawn for each datagram, from the seed. With `--scenario`, `adl_mock` writes a `scenario_datagram` event for each datagram a step met, and `stopped` lists the steps that were armed and met none (`scenario_idle`). `started` gains `scenario_features`, the actions this version knows, and `adl_mock --scenario-actions` prints them. The file and the events are in [Scenarios for the mock target](docs/user-guide/mock-scenarios.md). The mock target's page now says what it does with an upload whose file does not match its check value: it notes it in the log, stores the file, and ends the upload as completed, where a real target is expected to refuse it.
